# GameMaster AI

> AI 游戏化企业培训与实战陪练系统 · 面向游戏客服团队的本地可运行演示

GameMaster AI 把客服培训做成一场可以“打怪升级”的实战演练：AI 扮演不同性格的玩家发起真实工单，客服在对话中完成 SOP、安抚情绪、守住合规边界；系统用规则引擎 + 本地大模型评审给出五维评分与复盘，并把训练结果沉淀为个人段位、徽章和企业管理看板。

本项目是一套**无需构建、开箱即用**的演示系统：后端 FastAPI + SQLite，前端原生 JavaScript 单页应用，大模型默认接入本机 [Ollama](https://ollama.com/)，模型不可用时自动切换模板台词与纯规则评分，保证演示不中断。

## 快速开始

### 1. 准备本地大模型（推荐）

```bash
# 安装 Ollama 后，拉取一个中文对话模型（7B 适合 16GB 内存，27B 效果更好）
ollama pull qwen2.5:7b

# 确认 Ollama 已启动
curl http://localhost:11434/api/tags
```

模型选择策略：

1. 如果设置了 `GM_OLLAMA_MODEL`，优先使用指定模型；
2. 否则按 `qwen3.8:27b-mlx` → `qwen3:27b` → `qwen2.5:14b` → `qwen2.5:7b` → `llama3.1:8b` 的顺序自动匹配；
3. 都没有命中时，选本地第一个非 embedding / rerank 模型。

> 模型只影响对话质量与评审质量，不影响主流程。Ollama 不可用、超时或返回异常时，AI 玩家自动使用人格模板台词，结算自动退化为纯规则评分，页面仍可完整演示。

### 2. 启动服务

推荐使用一键脚本（需要本机有 `uv`）：

```bash
./run.sh
```

或手动启动：

```bash
python3.12 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
uvicorn app.main:app --host 127.0.0.1 --port 8787
```

打开浏览器访问 **<http://127.0.0.1:8787>**。

首次启动会自动创建 `data/gamemaster.db`，并写入演示租户「星海互娱」、6 名学员和 40 条历史训练记录。

### 3. 可选环境变量

`.env.example` 是配置参考。应用**不会自动读取 `.env`**，需要在启动前导出：

```bash
cp .env.example .env
set -a; source .env; set +a
./run.sh
```

常用配置见[配置项](#配置项)。

## 部署到 Render

仓库内置 `render.yaml`，可在 Render 上创建免费 Web Service：

1. 打开 [Render Dashboard](https://dashboard.render.com) → **New** → **Blueprint**，选择 GitHub 仓库 `theo-w/gm-ai`；
2. Render 读取 `render.yaml` 后创建服务，首次部署约 3–5 分钟；
3. 部署完成后访问分配的 `https://*.onrender.com` 域名。

也可以在 **New → Web Service** 手动填写：

| 配置项 | 值 |
| --- | --- |
| Repository | `https://github.com/theo-w/gm-ai` |
| Runtime | Python 3（`.python-version` 固定 3.12.3） |
| Build Command | `pip install -r requirements.txt` |
| Start Command | `uvicorn app.main:app --host 0.0.0.0 --port $PORT` |
| Health Check Path | `/api/health` |
| Plan | Free |

免费实例的限制与应对：

- **本地文件易失**：免费实例没有持久磁盘，SQLite 会在重部署、重启或休眠后清空；应用启动时会自动重新建库并写入演示种子数据，适合演示，不适合保存真实数据。需要持久化时请升级付费实例并挂载磁盘，或改用 PostgreSQL（需自行替换 `app/db.py` 数据层）。
- **休眠**：15 分钟无请求会休眠，下一次访问需约 1 分钟冷启动。
- **线上没有 Ollama**：应用会自动使用模板台词与纯规则评分，流程完整但 AI 对话质量下降。如需真实模型，在 Render 环境变量中把 `GM_OLLAMA_URL` 指向可公网访问的 Ollama 实例（注意鉴权与暴露风险），或参考 `app/engines/llm.py` 接入云端模型网关。
- **无登录鉴权**：当前是公开演示版，任何人都可访问和新建学员，请勿放入真实业务数据。

> 注意：本环境直接访问 `render.com` 主站可能超时，但 `dashboard.render.com` 与 Render API 正常。

## 演示路径

1. **训练大厅**：默认学员周玥已通关 8 关，可直接看到她的大厅档案、段位、徽章、闯关地图和历史训练。
2. **挑选关卡**：点击任意已解锁关卡打开「任务简报」，查看场景、AI 玩家画像、5 个考核目标和企业知识库。
3. **开始对练**：AI 玩家按人设发出第一条消息。输入客服回复后，系统会实时：
   - 命中 SOP 关键词并点亮目标；
   - 根据安抚/敷衍升级/忌语/越权承诺调整玩家情绪；
   - 在右栏显示情绪曲线、战术提示和 AI 证据。
4. **结束结算**：至少回复 1 次后可结束。AI 教练结合规则证据与完整对话生成评分、五维雷达、教练点评、段位经验与徽章/关卡解锁。
5. **管理看板**：顶部切换到「数据看板」，查看累计训练、通关率、平均分、首响、趋势、团队能力雷达、薄弱 TOP3、关卡分布、学员榜和 ROI 测算器。
6. **多学员**：右上角学员菜单可切换 6 名预置学员，或新建自己的学员档案；切换时若存在未结算对练，会把当前对局保留在「实战对练」标签中。

```
┌──────────────────────▼───────────────────────────────────────┐
│  FastAPI（app/api.py）                                       │
│  ├─ 学员进度 / 关卡解锁 / 任务简报                           │
│  ├─ 对练消息、提示、结算                                     │

│                                                              │
│  ┌─────────────────────┐  ┌──────────────────────────────┐   │
│  │ 规则与成长引擎       │  │ AI 中台适配层                 │   │
│  │ scorer.py            │  │ llm.py（Ollama /api/chat）    │   │
│  │ progress.py          │  │ prompts.py（人设 + 教练）      │   │
│  │ retriever.py（RAG）  │  │ 模板兜底                     │   │
│  └─────────────────────┘  └──────────────┬───────────────┘   │
│                                          │                   │
│  SQLite（data/gamemaster.db）            │                   │
│  tenants / trainees / runs / messages    │                   │
└──────────────────────────────────────────┼───────────────────┘
                                           ▼
                              ┌─────────────────────────┐
                              │ 本机 Ollama              │
                              │ qwen / llama 等中文模型  │
                              └─────────────────────────┘
```

关键设计：

- **前端零依赖**：无需 Node/npm，直接由 FastAPI `StaticFiles` 托管；图表为纯 SVG 手绘，避免图表库体积与网络依赖。
- **兜底优先**：模型层任何失败都不会阻塞训练或结算，只是降级质量。
- **规则可解释**：评分保留 rule / AI / 最终三组分数与命中证据，复盘里能看出差异。
- **多租户预留**：`tenants / trainees / runs` 带 `tenant_id`，`messages` 通过 `run_id` 归属；API 先校验 run 的租户再做消息读写，演示默认 `starsea`。

## 核心机制

### 1. Persona Engine（AI 玩家）

8 个预置玩家画像覆盖新手、小氪、暴躁、家长、概率论、老玩家、榜一、主播等典型类型：

| key | 玩家 | 画像 |
| --- | --- | --- |
| `newbie` | 小鹿 | 新手玩家 · LV.3 · 礼貌 / 困惑 / 需引导 |
| `buyer` | 布丁 | 小氪玩家 · LV.9 · 谨慎 / 首次充值 / 怕被骗 |
| `angry` | 峡谷火焰 | 排位玩家 · LV.12 · 暴躁 / 强势 / 要补偿 |
| `guardian` | 晨晨妈妈 | 玩家家长 · 未成年人 · 焦虑 / 追问退款 |
| `lawyer` | 概率论信徒 | 硬核玩家 · LV.38 · 理性 / 抠规则 / 质疑概率 |
| `veteran` | 熬夜冠军 | 老玩家 · LV.60 · 疲惫 / 见多识广 / 不耐烦 |
| `whale` | 夜皇 | 榜一玩家 · LV.88 · 高价值 / 直接施压 |
| `streamer` | 键盘侠客 | 人气主播 · 10w+ · 带舆论 / 情绪外放 |

人设提示词包含背景、性格、说话风格、当前情绪（1–10）、升级/降温触发条件，并强制 AI 不承认自己是模型、不替客服解决问题、一次只推进一个诉求。

情绪更新规则（每条学员回复）：

- 出现忌语 `+2`，越权承诺 `+1`；
- 道歉/共情用语 `−1`，服务动作/升级处理 `−1`；
- 每命中一个新 SOP 目标 `−1`，单轮命中 ≥2 个再 `−1`；
- 结果夹在 1–10，并立即影响下一条 AI 玩家的语气。

### 2. 知识库与轻量 RAG

内置 9 份企业知识文档（登录验证码、充值补单、掉线判负、未成年人退款、抽卡保底、服务器补偿、高价值用户、主播舆情、服务红线）。

`retriever.py` 使用“字符 bigram 重合 + 标签命中 + 标题命中”的 lexical 检索，无外部向量库依赖；`docs_for_ids()` 为关卡绑定知识。接入真实企业时，把 `search_docs` 替换为 pgvector / Milvus 等实现即可，上层返回结构不变。

### 3. 混合评分

**实时规则分析（每条消息，毫秒级）**

- 命中本关 SOP 关键词 → 新目标点亮；
- 检测忌语、对抗性表达、越权承诺、道歉/共情/服务动作、过短回复；
- 计算本条首响：上一条 AI 玩家消息时间 → 本次客服发送时间。

**结算（规则 40% + AI 教练 60%）**

| 维度 | 权重 | 评分来源 |
| --- | --- | --- |
| 共情能力 | 20% | 规则 40% + AI 60% |
| SOP 执行率 | 35% | 规则 40% + AI 60% |
| 情绪稳定度 | 20% | 规则 40% + AI 60% |
| 合规与专业 | 15% | 规则 40% + AI 60% |
| 首响效率 | 10% | 纯规则 |

规则细节：

- SOP 分 = 已命中目标的权重和（5 个目标权重合计 100）；
- 共情从 30 分起，按共情目标、道歉、共情词数量、服务动作、礼貌用语加分，按忌语/负面词扣分；
- 情绪稳定从 100 分起，每条忌语扣 16、每个负面词扣 4，有忌语时上限 72；
- 合规从 78 分起，命中合规目标 +10、无违规 +10，越权承诺每条 −18、忌语 −8；
- 首响映射：≤8 秒 100，≤15 秒 95，≤25 秒 88，≤40 秒 78，≤60 秒 66，≤90 秒 55，>90 秒 45；过短回复额外扣分。

阈值与扣分：

- 通过线：**总分 ≥ 80 且至少 2 条学员回复**；
- 每使用 1 次战术提示扣 2 分，单局最多扣 6 分；
- 少于 2 条回复时总分最高 68（结算接口本身要求至少 1 条）；
- 等级：S ≥ 95，A ≥ 88，B ≥ 80，C ≥ 65，D < 65。

AI 教练：

- 只输出 JSON：`empathy / sop / emotional / compliance / feedback / strengths / summary`；
- 温度 0.15，JSON mode，超时 120 秒；
- 解析失败或模型不可用时，自动改用纯规则分，并在复盘中注明；
- 为避免“规则说 5/5 已完成、AI 却点评未完成”的自相矛盾，已加入 prompt 约束与后端过滤：当规则判定全部目标达成时，会过滤 AI 点评中“未完成/漏掉/缺失/跳过”等反向结论，并把矛盾总评替换为执行细节建议。

### 4. 成长与游戏化

- 关卡：8 关，按青铜 → 白银 → 黄金 → 铂金 → 王者分段，逐关解锁，通过线 80；
- 经验：通过 `round(关卡 XP × 总分/100 × 1.5)`；未通过 `round(关卡 XP × 0.25)`；
- 段位：青铜 0 / 白银 300 / 黄金 700 / 铂金 1200 / 星耀 1800 / 王者 2600 XP；
- 徽章：首战告捷、青出于蓝、共情大师、疾风之刃、满分教官、通关王者；
- 每次结算返回 `rank_up / badges_new / unlocked_level / next_level`，前端展示奖励条并提供“挑战下一关”。

### 5. 管理看板与 ROI

`GET /api/admin/overview` 聚合：

- 累计局数、学员数、通关率、平均分、平均首响、累计节省带教成本；
- 近 14 天训练局数 + 平均分趋势；
- 团队五维能力雷达与薄弱 TOP3；
- 各关卡尝试数、通过率、平均分；
- 学员榜（XP、段位、通关数、均分）；
- 最近 12 条训练记录。

ROI 测算器在前端实时计算：

```
节省小时 = 结算局数 × 每局替代带教分钟 / 60
节省金额 = 节省小时 × 导师时薪
```

默认每局 25 分钟、导师时薪 ¥120；页面可调训练局数、每局分钟、时薪和新员工人数，并展示月度/年度金额、节省小时和每名新员工分摊成本。该结果是指标估算，不是财务结算数据。

## API 一览

所有接口前缀为 `/api`。除 `health`/`meta` 外，学员、训练、看板接口都按 `X-Tenant` 请求头隔离，未传时使用 `GM_TENANT`（默认 `starsea`）。

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/health` | 服务、模型、数据库状态 |
| GET | `/api/meta` | 租户、关卡、玩家画像、段位、评分维度 |
| GET | `/api/trainees` | 租户下学员列表 |
| POST | `/api/trainees` | 新建学员，body `{"name":"昵称"}` |
| GET | `/api/trainees/{id}/progress` | 学员档案、关卡状态、徽章、统计、最近记录 |
| GET | `/api/knowledge/search?q=...&limit=3` | 知识库检索 |
| POST | `/api/runs` | 开始对练，body `{"trainee_id":"...","level_id":"..."}` |
| GET | `/api/runs/{run_id}` | 对练快照（含 transcript、实时目标、结果） |
| POST | `/api/runs/{run_id}/messages` | 发送客服回复，body `{"content":"..."}` |
| POST | `/api/runs/{run_id}/hint` | 获取下一条未完成目标的战术提示 |
| POST | `/api/runs/{run_id}/finish` | 结算本局，返回评分、复盘、奖励与下一关 |
| GET | `/api/admin/overview` | 管理看板聚合数据与 ROI 基线 |

示例：

```bash
curl -s http://127.0.0.1:8787/api/health

curl -s -H 'X-Tenant: starsea' http://127.0.0.1:8787/api/trainees

curl -s -X POST http://127.0.0.1:8787/api/runs \
  -H 'Content-Type: application/json' -H 'X-Tenant: starsea' \
  -d '{"trainee_id":"t_zhouyue","level_id":"bronze-1"}'
```

`POST /messages` 响应中的 `turn` 包含：命中目标、情绪变化、首响毫秒数、AI 回复耗时、是否触发模板兜底、当前回合数。`/finish` 返回 `result`（评分与复盘）和 `meta`（经验、段位、徽章、解锁关卡）。

## 数据模型

SQLite 共 4 张业务表，核心实体带 `tenant_id`，消息通过 `run_id` 从属：

- `tenants`：租户（演示默认「星海互娱」，`starsea`）；
- `trainees`：学员档案、XP、头像、是否种子数据；
- `runs`：对练局，记录状态、回合数、总分、评分 JSON、评审 JSON、提示次数、平均首响、情绪、时间；
- `messages`：逐条对话，记录角色、内容、时间、首响毫秒、规则分析 JSON、序号。

评分 JSON 保存最终五维分、rule/AI 分、目标命中、点评、奖励、通关状态等；种子历史记录额外带 `seeded=true`，前端会显示「历史演示数据」标识。

```bash
# 先停止服务，再删除数据库（会清空所有本地训练记录）
rm -f data/gamemaster.db data/gamemaster.db-wal data/gamemaster.db-shm

# 重新启动后自动建库并重新生成种子数据
./run.sh
```

> 重置会丢失本机新建学员与训练记录，请只在不需保留数据时执行。

## 已知限制与后续扩展

本项目定位是**可运行、可演示的产品原型**，以下能力尚未实现或仅为演示级：

- **认证与权限**：没有登录、JWT、RBAC；`X-Tenant` 由客户端传入，生产环境必须增加身份校验与租户白名单；
- **数据安全**：SQLite 明文存储，未实现字段加密、审计日志、备份策略；生产建议 PostgreSQL + 行级安全 + KMS；
- **ASR / TTS**：当前只支持文本对练；可在 `app/engines/` 增加语音识别与语音合成适配层；
- **向量 RAG**：当前是 lexical 检索，语义泛化有限；可替换为 embedding + 向量库，接口保持 `search_docs` 结构；
- **实时流式输出**：AI 回复为一次性返回，没有 SSE/WebSocket 流式播放；
- **评测稳定性**：AI 教练评分受本地模型能力影响；已提供纯规则降级与规则/评委分对照，但生产环境仍建议抽样人工校准；
- **前端规模化**：单文件 demo 级 SPA，未做组件化、国际化、可访问性完整验收；
- **运营能力**：没有题库后台、租户管理后台、课程编排、消息推送、导出报表；
- **并发与任务队列**：SQLite + 同步文件库适合单机演示；多实例部署需换数据库并引入任务队列。

## 目录结构

```
game-master-ai/
├── app/
│   ├── api.py                # HTTP API：学员、对练、结算、看板
│   ├── main.py               # FastAPI 入口 + 静态资源托管
│   ├── config.py             # 环境变量、段位、评分维度
│   ├── db.py                 # SQLite 连接与建表
│   ├── seed.py               # 演示租户/学员/40 条历史数据
│   ├── content/
│   │   ├── levels.py         # 8 个关卡、5 个 SOP 目标/关
│   │   ├── personas.py       # 8 类 AI 玩家画像
│   │   ├── knowledge.py      # 9 份企业知识文档
│   │   └── lexicon.py        # 忌语、共情词、服务动作等词典
│   └── engines/
│       ├── llm.py            # Ollama 适配、自动选模、健康检查
│       ├── prompts.py        # 玩家/教练提示词与模板兜底
│       ├── scorer.py         # 规则分析、AI 评审解析、混合评分
│       ├── progress.py       # 关卡解锁、段位、徽章、XP
│       └── retriever.py      # 轻量知识检索
├── web/
│   ├── index.html            # 单页应用入口
│   ├── styles.css            # 深色游戏 HUD 视觉
│   ├── app.js                # 大厅/对练/看板/复盘交互
│   └── charts.js             # 纯 SVG 趋势图与雷达图
├── data/                     # 运行后生成 SQLite（默认）
├── .env.example              # 配置参考（需手动 source）
├── requirements.txt
├── run.sh                    # 一键创建虚拟环境并启动
└── README.md
```
